# 壁ラジ1

## 概要

壁ラジ1は、壁ラジ24へ進む前の実証実験です。モブ子が一人でLocal LLMに話題の入口と展開を任せ、Shared TTSで読み上げる「一人語りの雑談ラジオ」として動かします。

あまかわちゃんや視聴者との会話ではなく、モブ子自身の独り言です。身近な日常のどうでもいい話を中心にしつつ、少しだけ考え事や意識高めの方向へ寄り道します。人生訓、自己啓発、大げさな結論、ポエム調は抑えますが、完全には消さず、雑談の中に少量残します。

## この実験で確認すること

- 事前に固定した台本なしで、Local LLMが話題を選び、どこへ着地するか
- 直近の発話を短期Contextとして使い、同じ話題をしばらく自然に展開できるか
- 再生中に次の発話を先行生成するQueueで、発話が途切れにくくなるか
- TTSと再生の間に短い間を置くことで、発話の切り替えを自然にできるか
- Stop / PauseやProvider停止時に、未完了の生成・TTS・再生を安全に片付けられるか

開始時の話題は候補からランダムに選ぶことも、入口を与えずLLM自身に選ばせることもできます。候補は話題を固定する台本ではなく、最初のきっかけに限定します。数発話ごとに機械的に話題を変更する設計にはせず、前の発話を受けて同じ話題を広げ、自然な区切りで移ることを狙います。

## 実行形態

WallRadio1の実行コードは、実行基盤である [`amakawachan-assistant`](https://github.com/amakawa-chan/amakawachan-assistant) の `Radio/WallRadio1.ps1` と共有Radio / TTS境界で管理します。KabeRadioへ実行コードを複製しません。

実行条件はsmoke（5分）とbounded（最大60分）です。各runでは、発話本文、時刻、LLM / TTS / Playbackの状態、エラー、停止理由、実行条件をrun manifestとイベントログへ保存します。成功した発話は既存のSession Markdown互換形式でも保存できます。

生成runフォルダーや一時WAVは実行環境側の成果物です。KabeRadioへ無加工のログを追加せず、公開・保存するエピソードを選んだ場合だけ、通常の壁ラジ台本へ整形して `episodes/` に登録します。WallRadio1自体には固定の `script.md` はありません。

## 配信・録画との関係

初期確認では、OBS StudioでWallRadio1の16:9画面とデスクトップ音声を取り込みます。YouTube Liveは限定公開での手動確認を前提とし、自動公開や24時間連続運転はこの実験の対象外です。

OBS連動を使う場合も、Stream Key、OAuth token、OBS WebSocket passwordはKabeRadio、実行manifest、イベントログへ保存しません。公開配信へ進める前に、録画で音量、発話切替、無音、Stop後の終了状態を確認します。

## 次の判断

WallRadio1で自然な話題展開と音声の連続性を確認した後、面白かったrunだけを選んで、固定台本のエピソードとして編集・保存します。実験中の生成結果をそのままCanonical Episodeへ昇格させず、繰り返し現れた性質だけをCharacter Profileへ反映するという、KabeRadioのPersona運用方針に従います。
